# nram-lab-cron-codes

## Описание

Репозиторий с кодами для создания бекапов NRAM LAB, для запуска с помощью cron.
Планируется расширение. БЕЗ ЗАВИСИМОСТЕЙ, ЧИСТЫЙ ПИТОН.
На текущий момент умеет:

- Делать бекап compose.
- Делать бекап базы данных.
- Обновлять ОС (ubuntu).
- Проверять контрольные суммы для базы данных и сравнивать их, т.е. чекать целостность бекапа.
- Отправлять сообщение в телегу о том, что бекап сделан, с результатом.

Для запуска задач использовать скрипты .py.

Проверено на **python 3.12.3**

Используемые технологии:

- python3
- cron
- docker.io (sudo apt install docker-io docker-compose)
- helix (sudo add-apt-repository ppa:maveonair/helix-editor && sudo apt update && sudo apt install helix)

## Шпаргалка cron

Cron использует синтаксис из 5 полей для планирования задач:

- минута (0-59),
- час (0-23),
- день месяца (1-31),
- месяц (1-12),
- день недели (0-7, где 0/7=воскресенье).

После полей идет команда запуска.

### Управление cron

```bash
  crontab -e # редактировать задания текущего пользователя.
  crontab -l # просмотреть задания.
  crontab -r # удалить все задания.
```

### Синтаксис полей

- *    — любое значение
- ,    — список (0,5,10)
- -    — диапазон (1-5)
- */n  — шаг (каждые n, напр. */15)
- /n   — с начала периода шагом n (0/n)
- Директива L — последний день (для дней/месяцев).

### Специальные строки

- @reboot   — при загрузке
- @hourly   — ежечасно (0 ** **)
- @daily    — ежедневно (0 0 ** *)
- @weekly   — еженедельно
- @monthly  — ежемесячно
- @yearly   — ежегодно

### Примеры

```bash
# Приклад
# Бекап компосов в 8 утра каждого 10 числа месяца из текущего юзера
0 8 10 * * python3 ~/nram-lab-cron-codes/make_compose_backups.py

# бекап базы в 14-30 каждый день
30 14 * * * python3 ~/nram-lab-cron-codes/make_database_backup.py

# Теоретические примеры
# Каждую минуту
* * * * * /usr/bin/python3 /path/to/script.py >> /var/log/script.log 2>&1

# Каждый час
0 * * * * cd /path/to/dir && /path/to/venv/bin/python script.py

# Ежедневно в 3:00
0 3 * * * /usr/bin/python3 /home/user/script.py

# Каждые 15 мин по будням (1-5)
*/15 * * * 1-5 python3 /opt/task.py

# В 7:30 по воскресеньям
30 7 * * 0 /usr/bin/python3 /script.py
```

## Введение в контрольные суммы

Контрольная сумма — это строчное значение, вычисленное по набору данных с помощью определённого алгоритма и используемое для проверки целостности данных при их передаче или хранении. Это как цифровой отпечаток пальца файла — любое изменение хотя бы одного байта приводит к изменению контрольной суммы.

Технически контрольная сумма является результатом хеш-функции, которая преобразует данные произвольной длины в значение фиксированной длины.

### Зачем применяются контрольные суммы

Основные цели использования контрольных сумм:

- Проверка целостности данных — обнаружение случайных повреждений при передаче по сети или хранении на диске
- Обнаружение изменений — выявление модификаций файлов (например, для обнаружения вирусов)
- Быстрое сравнение данных — определение идентичности файлов без побайтового сравнения
- Проверка загрузок — подтверждение корректности скачанных файлов и программ

Контрольная сумма не гарантирует подлинность источника, но подтверждает целостность полученных данных.
​

### Основные алгоритмы вычисления контрольных сумм

**CRC (Cyclic Redundancy Check)**

Алгоритм|Размер|Применение|
|-|--------|---|
CRC-8|8 бит|Bluetooth, микроконтроллеры
CRC-16|16 бит|HDLC, Bluetooth, GSM-сети
CRC-32|32 бита|Ethernet, ZIP-архивы, файловые системы
CRC-64|64 бита|Системы хранения, архивы

Особенности: Быстрые, простые, хорошо обнаруживают случайные ошибки, но уязвимы к целенаправленным изменениям.

**Криптографические хеш-функции**

Алгоритм|Размер хеша|Статус|Применение
|-|--------|---|---|
MD5|128 бит|Устарел|Только для некритичных данных
SHA-1|160 бит|Deprecated|Не рекомендуется
SHA-256|256 бит|✓ Рекомендуется|Бэкапы, дистрибутивы ПО
SHA-512|512 бит|✓ Максимальная надёжность|Критичные данные

Особенности: Криптографически стойкие, практически невозможно создать два разных файла с одинаковым хешем (коллизии).
